# Future Engineering & Architecture Roadmap

本ドキュメントは、`termway` の長期的な保守性・スケーラビリティ・堅牢性を向上させるためのアーキテクチャおよびエンジニアリング上の技術的課題（Technical Debt）と今後の改善ロードマップをまとめたものです。

---

## 1. `TermwayState` のドメイン分割（God Object アンチパターンの解消）

### 現状と課題
`src/compositor/state.rs` 内の `TermwayState` 構造体は、Smithay コンポジタの要求によりイベントループの中心に配置されていますが、現在以下の多岐にわたる責務を1つの構造体で一括保持しています：
- **Wayland プロトコルコア**: CompositorState, XdgShellState, ShmState, XWaylandShellState
- **入力機器・Seat 管理**: SeatState, Seat, KeyboardHandle, PointerHandle
- **ウィンドウライフサイクル・管理**: Wayland サーフェス, X11 サーフェス, ManagedWindow, ポップアップ管理
- **インタラクション状態マシン**: ウィンドウの移動・リサイズ（`WindowDragState`）、最大化/最小化、タスクバー状態
- **描画・ループ制御**: `dirty` フラグ, `running` フラグ, 各種タイマー

これにより、新機能の追加やバグ修正のたびに `TermwayState` への修正が集中し、結合度が高くなっています。

### 改善方針
`TermwayState` をオーケストレーターとして位置づけ、ドメインごとに凝集度の高いサブモジュールへ分割・委譲します：
- **`WindowManager`**:
  - ウィンドウ（Wayland / X11）の Z-order、フォーカス、ジオメトリ、ドラッグ・リサイズ・最大化・最小化状態の管理。
- **`InputManager`**:
  - シート、キーボード、ポインタのハンドリングと、入力イベント（クリック・ドラッグ・ホバー）のルーティング。
- **`ShellManager`**:
  - XDG Shell、XWayland Shell、およびポップアップライフサイクルの管理。

## 2. フレームレンダリング・画像エンコードのパイプライン分離（非同期化）

### 現状と課題
現在、フレームの Pixman レンダリングおよび端末用画像プロトコル（Kitty Graphics Protocol / Sixel）へのエンコード処理は、Smithay のメインイベントループ（Calloop）内で同期的に実行されています（`src/compositor/mod.rs`）。
- **Sixel エンコード**: RGB332 への量子化、パレット生成、RLE 圧縮
- **Kitty エンコード**: チャンク分割および Base64 エンコード
- **ターミナル出力**: 標準出力へのエスケープシーケンス書き出し

高解像度端末や大量の画面更新（動画再生、激しいスクロール等）が発生した際、エンコード処理の CPU 負荷によりイベントループがブロックされ、マウスポインタやキー入力の応答レイテンシが増加する原因となります。

### 改善方針
レンダリングパイプラインをイベント駆動型のワーカースレッドへ分離します：
1. **イベントループ**: ダメージ領域の収集とサーフェスバッファのコミット通知のみを高速にディスパッチ。
2. **レンダリング/エンコードスレッド**: ダメージ通知をチャネル経由で受け取り、バックグラウンドで画像エンコードを実行。
3. **I/O スレッド**: 完成したエンコードデータを非同期に標準出力へ flush。最新フレームへの間引き（Frame Dropping / Rate Limiting）を導入して端末のバッファ溢れを防止。

## 3. レガシー X11 エンジン (`src/engine.rs`) と Wayland コンポジタの一本化

### 現状と課題
リポジトリ内には現在、2つの独立した実行エンジンが存在しています：
1. **Smithay ベース Wayland コンポジタ** (`src/compositor/`): XWayland を内蔵し、Wayland および X11 アプリケーションを透過的に実行（デフォルト）。
2. **レガシー X11 エンジン** (`src/engine.rs`): `Xvfb` + `openbox` + X11 SHM を使用して画面をキャプチャし描画する初期実装。

2系統のエンジンが並存しているため、ウィンドウ装飾、最大化/最小化、クリップボード同期、端末サイズ追従などの新機能を追加する際、両方のエンジンに二重実装・二重テストが必要となり、メンテナンスコストが増大しています。

### 改善方針
- XWayland の動作が十分に安定しているため、レガシー `src/engine.rs`（`--x11` スタンドアロンモード）を将来のメジャーバージョンに向けて非推奨化（Deprecated）。
- X11 アプリケーションの実行は Smithay + XWayland パイプラインへ統一し、コードベースの冗長性を大幅に削減。

---

## 4. エラーハンドリング体系の型安全化（Robust Error Handling）

### 現状と課題
パニック（`.unwrap()`）の排除は完了していますが、エラー型の伝播において `Box<dyn std::error::Error>` や `Result<(), String>` などのアドホックな型が一部に残っています。

### 改善方針
- `thiserror` クレートを導入し、モジュール単位の型安全なエラー列挙体（`CompositorError`, `SessionError`, `ProtocolError` 等）を定義。
- アプリケーション障害時のフォールバック処理を強化（例: クライアントアプリが異常終了しても、コンポジタ自体はエラーバナーを表示して安全に待機・再起動可能にする）。

---

## 5. ロードマップ概要

| マイルストーン | 項目 | 優先度 | 期待効果 |
| :--- | :--- | :---: | :--- |
| **v0.4** | `TermwayState` のドメイン分割 (`WindowManager`, `InputManager`) | 中 | コード可読性・拡張性の向上、テスト容易性 |
| **v0.5** | レンダリング・エンコードのワーカースレッド分離 (Async Encoding Pipeline) | 高 | 高解像度・高負荷時の入力レイテンシ削減 |
| **v0.6** | 型安全なエラー体系 (`thiserror`) の統一とフォールバック強化 | 中 | 耐障害性の向上、エラー診断の容易化 |
| **v1.0** | レガシー X11 エンジン (`src/engine.rs`) の完全統合・コードベース一本化 | 高 | アーキテクチャの単純化、保守コスト半減 |
