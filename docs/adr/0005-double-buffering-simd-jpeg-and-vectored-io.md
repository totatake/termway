# ADR-0005: 完全非同期パイプライン・SIMD JPEG・ベクタード I/O による描画スループット最適化

## ステータス

**承認済み・実装完了 (Implemented)** (2026-11)

## コンテキスト

termway は YouTube や 3D GUI 等の高フレームレート・大解像度ストリーミングにおいて、1080p フルフレーム描画時に約 15〜30ms のレイテンシを要していた。
Chrome Trace による詳細プロファイリングの結果、以下のボトルネックが判明した:
1. **フレーム組み立て時の 256KB memcpy**: 制御ヘッダ・画像ペイロード・サフィックスを単一の `frame_buf` に結合する際のメモリコピー。
2. **スカラー JPEG エンコード所要時間**: 1080p フルフレームで約 13ms を要し、色変換・FDCT・量子化が CPU 律速。
3. **エンコードと PTY 送信の直列同期**: 同一ワーカースレッド内でエンコード直後に `write_all` を実行するため、実効フレーム周期が $T_{enc} + T_{write}$ に伸び、PTY バッファの空き待ちでエンコードが停止していた。

## 決定事項

1. **PTY 送信のベクタード I/O (`writev`) 採用**:
   - `vmsplice`（Linux ゼロコピーパイプ送信）は PTY スレーブ端末との互換性不足およびページ境界アライメント制約、ページ再利用レースのリスクから**不採用**とした。
   - POSIX 準拠の `libc::writev` による scatter-gather 出力を採用し、`prefix_buf`（プレフィックス）・`payload`（エンコーダ出力）・`suffix_buf`（サフィックス）の 3 スライスをカーネル空間で一括送信する。
2. **純粋 Rust JPEG エンコーダの AVX2 / ARM NEON SIMD ベクトル化**:
   - 外部 C ライブラリ（libjpeg-turbo 等）への依存を避け、シングルバイナリ・ゼロ依存・クロスコンパイル容易性を堅持する純粋 Rust 実装を採用。
   - 16x16 MCU 単位の単一メモリアクセス融合色変換、AVX2 / NEON 転置 2D FDCT、64bit 並列量子化を実装。
   - **INV-4（スカラーとのビット完全一致）** を必須不変条件とし、丸め誤差の生じる 16bit 近似命令（`mulhi` 等）を排除して `i32` 完全一致演算を保証。
3. **Double-Buffering パイプライン分離**:
   - `termway-async-render`（Encode スレッド）と `termway-async-write`（Write スレッド）の 2 スレッドに分離。
   - 2 面の `EncodedFrame` ピンポンバッファ（`WriteHandoff`）により、Write スレッドが送信中に Encode スレッドが次フレームを並行エンコード。
   - **INV-1（エンコード後のフレーム Drop 禁止・完全順序保証）**: 端末エミュレータ側の画像参照状態・差分状態の破壊を防ぐため、`ready` キュー容量を 1 とし、書き込み完了まで Encode 側が待機するランデブー方式を採用（Drop はエンコード前の `pending_job` でのみ許容）。
   - **INV-5（安全なシャットダウン順序）**: Encode スレッド終了 → Write スレッド終了 の順に join し、端末同期描画ブラケット（`?2026`）の不整合を完全に防止。
4. **安全弁と後方互換性**:
   - `TERMWAY_JPEG_SIMD=0`: スカラーエンコーダ強制。
   - `TERMWAY_PIPELINE=serial`: M1 相当の直列単一ワーカースレッド強制。

## 結果と影響

- 1080p JPEG フルフレームエンコードが **13.07ms から 3.98ms へ 3.29倍高速化**。
- パイプライン化により実効フレーム周期が $T_{enc} + T_{write}$ から $\max(T_{enc}, T_{write})$ へ短縮。
- 136 件のユニット・統合テスト（`PIP-001`〜`PIP-005` 含む）により、ビット完全一致、順序保証、非欠落、シャットダウン安全性を実証。
